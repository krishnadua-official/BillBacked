# Working in this Jac project

This is a [Jac](https://www.jaseci.org/) project. Jac's syntax has evolved and
is easily confused with Python or JSX -- before writing or editing `.jac`
files, consult the reference guides bundled with the compiler.

## Reference guides

The `jac` CLI ships curated reference guides ("Agent Skills") -- the
authoritative spec for writing correct, idiomatic Jac:

- `jac guide` -- list every available guide
- `jac guide <name>` -- print a guide (e.g. `jac guide jac-types`)
- `jac guide --search <keyword>` -- find guides by topic
- `jac guide --json` -- machine-readable output for tooling

Start with `jac guide jac-core-cheatsheet` and `jac guide jac-types`.

## Validate your work

- `jac check <file>` -- type-check and lint. Compiler diagnostics link to the
  relevant guide; follow the `-> run 'jac guide ...'` hints.
- `jac run <file>` -- execute a Jac script.
- `jac start --dev main.jac` -- start a web-app or service in dev mode
  (hot-reload for client files; restart for server changes). Use this instead
  of `jac run` for apps.
- `jac browse <action>` -- QA a running app in a headless browser:
  `jac browse open localhost:8000`, then `snapshot` (accessibility tree with
  `@e1`-style refs), `click @e5`, `fill '#email' user@example.com`, `screenshot`, `close`.

_Generated by `jac create`._

## BillBacked architecture

- `main.jac` is the only route table.
- `components/DashboardLayout.jac` is the authenticated application shell.
- `components/InvoiceData.cl.jac` is the single typed source for prototype
  invoice history. Do not add invoice fixtures inside page or sidebar
  components.
- `components/AccountMenu.jac` owns both header and sidebar account-menu
  variants. Add account actions there so both surfaces stay consistent.
- `services/negotiation.sv.jac` is the single source for the fictional
  outbound-call case, negotiation guardrails, and ElevenLabs request boundary.
  Do not copy its demo invoice into page or sidebar components.
- `components/ui/` contains the shared jac-shadcn primitives; prefer composing
  these over creating page-specific replacements.
- `components/ui/button.jac` is the product-owned Nice Design action primitive.
  Use `primary`, `secondary`, or `tertiary` instead of rebuilding button styles
  at call sites. Preserve these variants if the jac-shadcn registry is updated.

The audit flow is currently client-only, while `services/pricing.sv.jac`
provides the Medicare price lookups. The optional call sandbox uses only its
fixed fictional case. Never send an uploaded bill or real patient information
to telephony until consent, privacy, retention, security, and vendor-contract
requirements are implemented. There is no persisted invoice model yet, and the
deleted Jac starter notes service is not part of BillBacked.

## Maintainability gate

Before considering any implementation complete, ask:

- Is this a durable solution or a quick patch that only fixes the current
  screen?
- Can existing shared components, typed data sources, layout primitives, or
  design tokens solve it before adding something new?
- If a new pattern is necessary, should it become a reusable component or
  shared helper instead of remaining page-specific?
- Does the change preserve one unified design system rather than recreating
  near-duplicate custom components?
- Are names, file placement, types, and boundaries clear enough that a future
  agent can find the source of truth and understand why the code exists?
- Were obsolete paths, duplicated fixtures, dead components, and misleading
  starter code removed or clearly documented?

Prefer the smallest reusable abstraction that removes real duplication. Do not
create abstractions speculatively, but do not accept copy-paste or one-off CSS
when the project already has a shared pattern. When adding a new architectural
source of truth, update this file so future agents know where it lives.
